# Simpul Batch P7 — Izin AI per Folder + Audit, ANN IVF, Saran Tag

Tanggal: 2026-11-13. Batch ketujuh implementasi PRD "Simpul", menutup empat
item PRD: izin akses AI berlapis (DIF-04/AI-42, MUST), log audit akses AI
(AI-43, MUST), evaluasi ANN IVF vs brute-force (AI-31, SHOULD), dan saran tag
(AI-26, COULD).

## Cakupan

1. **`AiAccessPolicy`** (`packages/simpul_core/lib/src/ai_permissions.dart`) —
   kebijakan akses AI atas vault, dikonfigurasi lewat
   `<vault>/.simpul/ai-permissions.json`:
   ```json
   {
     "default": "izin",
     "folders": {"rahasia": "tolak", "draft": "tanya"},
     "notes": {"rahasia/kunci.md": "tolak"},
     "tags": {"pribadi": "tolak"}
   }
   ```
   Nilai diterima dalam Bahasa Indonesia dan Inggris (`izin`/`izin penuh`/
   `allow`, `tanya`/`tanya dulu`/`ask`, `tolak`/`deny`). Keputusan efektif =
   paling membatasi antara default, aturan folder prefix TERPANJANG (folder
   lebih spesifik meng-override yang lebih luas), aturan catatan eksak, dan
   aturan tag (prefix tag bersarang, gaya Obsidian `pribadi/keluarga`).
2. **`AiAuditLogger`** (AI-43) — satu baris JSONL per pemanggilan tool di
   `<vault>/.simpul/ai-audit.jsonl`: `{ts, tool, target, decision, detail?}`.
   Isi catatan tidak pernah dilog. Append + flush per entri.
3. **`AiAccessDenied`** — dilempar saat kebijakan menolak; bridge mengubahnya
   menjadi hasil tool `isError` + baris audit. Status `tanya` (ask) di
   tooling headless diperlakukan ditolak (butuh persetujuan manusia).
4. **Enforcement di Simpul Bridge (AI-44)** — seluruh 7 tool ter-wire:
   `search`/`semsearch` memfilter hasil terlarang dan melaporkan `filtered`;
   `backlinks` memfilter sumber; `read_note` menolak eksak; `clusters` dan
   `suggest_links` mengecualikan catatan terlarang sebelum graf dibangun.
   Policy dimuat ulang SETIAP tool call sehingga perubahan izin berlaku
   seketika (DIF-04). Config rusak → fallback `denyAll` (fail-closed).
5. **`IvfFlatIndex`** (`packages/simpul_core/lib/src/ivf_index.dart`, AI-31) —
   ANN IVF-Flat: k-means deterministik (centroid awal = vektor input berjarak
   merata, tanpa RNG), search = ranking centroid → `nprobe` klaster → rerank
   eksak. Untuk evaluasi ADR-06, bukan default pencarian.
6. **`TagSuggester`** (`packages/simpul_core/lib/src/tag_suggester.dart`,
   AI-26) — saran tag dari centroid tag yang ada (mean embedding catatan
   pemilik tag, L2-normalized); skor cosine; eksklusi tag milik sendiri dan
   tag nested; batas 5000 catatan (fail-closed). Saran saja — penerapan
   selalu butuh persetujuan pengguna.
7. **`tagsOf(Set<String>)` di `VaultIndex`** — tag per path untuk kedua
   backend (SQLite JOIN tabel `tags`/`notes`; JSON filter). Dipakai bridge
   hanya bila ada aturan tag.
8. **CLI `simpul suggest-tags <vault> [--limit N] [--min-score S]`** —
   output JSON `{suggestions: [{path, tag, score}]}`.

## Keputusan desain

- **Config file sebagai switch, bukan field tersimpan** — enforcement murni
  dari `ai-permissions.json`. Field `ai_access` yang tersimpan di indeks
  (default `'ask'` sejak P0) TIDAK dipakai: baris lama bernilai `'ask'`
  akan menolak semua catatan secara diam-diam. Tidak ada file config =
  policy off (AI-01: AI opsional).
- **Longest-prefix-wins untuk folder, bukan akumulasi** — aturan folder
  lebih spesifik menggantikan yang lebih luas, lalu hasilnya digabung
  most-restrictive dengan lapisan lain. Bug awal (akumulasi most-restrictive
  antar folder) terdeteksi oleh test: `'a' = deny` + `'a/b' = allow` harus
  menghasilkan `allow` untuk `a/b/c.md`.
- **`tanya` = ditolak di headless** — bridge tidak punya kanal manusia;
  membolehkan `ask` berarti melewati persetujuan. Pesan error menjelaskan
  bahwa butuh persetujuan manusia.
- **CLI manusia tidak difilter** — `simpul search`/`semsearch` adalah alat
  pengguna sendiri; hanya bridge (permukaan AI) yang menegakkan kebijakan.
- **Audit tidak pernah memuat konten** — hanya tool, target (query/path),
  keputusan, dan detail ringkas (mis. jumlah `filtered`).
- **IVF bukan default** — lihat hasil ADR-06 di bawah; brute-force tetap
  dipakai sampai vault cukup besar dan berklaster.
- **Saran tag deterministik** — centroid + cosine, tanpa RNG; tie-break
  leksikal agar output stabil.

## Hasil evaluasi ANN (AI-31, untuk ADR-06)

- Data acak uniform (1024 vektor dim 64, 32 klaster, nprobe=4): recall@10
  hanya **0.364** — IVF tidak cocok untuk data tanpa struktur klaster.
- Data berklaster (20 klaster × 50 vektor, nprobe=1): recall@10 = **1.000**
  dengan memindai hanya ~5% vektor.
- **Keputusan**: brute-force tetap default. IVF tersedia sebagai opsi
  terukur untuk vault besar yang berklaster (struktur klaster sudah
  tersedia dari Louvain, GRA-L05).

## Traceability PRD

- **DIF-04**: tiga status (`izin penuh`/`tanya dulu`/`tolak`) per
  folder/catatan/tag; perubahan berlaku seketika (policy reload per call);
  catatan `tolak` tidak pernah muncul di hasil, konteks, atau log prompt.
- **AI-42**: kebijakan berlapis dengan semantik most-restrictive +
  longest-prefix; fail-closed pada config rusak.
- **AI-43**: audit JSONL siapa/alat/catatan/waktu/diizinkan-atau-ditolak.
- **AI-31**: `IvfFlatIndex` + hasil evaluasi terdokumentasi (ADR-06).
- **AI-26**: `TagSuggester` — saran saja, penerapan butuh persetujuan.

## Limitasi

- Aturan frontmatter per-catatan (`ai-access:` di YAML) belum di-parse —
  permukaan UI masa depan; config file sudah mencakup kebutuhan MUST.
- Filter tag di `search`/`semsearch` bridge memerlukan lookup `tagsOf` per
  kandidat — hanya dijalankan bila ada aturan tag.
- `IvfFlatIndex` belum terhubung ke jalur pencarian utama (sesuai ADR-06,
  brute-force tetap default).
