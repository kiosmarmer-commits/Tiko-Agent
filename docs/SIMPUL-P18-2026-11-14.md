# Simpul P18 — Delta Sync Dua Arah, TUI Interaktif, Tema & Settings (2026-11-14)

Batch P18 mencakup tiga area: (1) sinkronisasi delta dua arah antar-perangkat
(lanjutan SEC-20..22), (2) TUI interaktif paritas Hermes, dan (3) konsistensi
tampilan lintas platform + halaman Settings di aplikasi desktop/web Flutter.

## 1. Delta Sync Dua Arah Antar-Perangkat (SEC-20..22 backlog)

**Modul**: `packages/simpul_core/lib/src/vault_delta_sync.dart`

Model offline tanpa server: dua perangkat bertukar dua artefak —

- **Jurnal** (`.simpul/sync/journal.json`): identitas perangkat (`deviceId`),
  revisi, peta `path → {hash, size, mtimeMs, rev}`, tombstone hapus, dan daftar
  peer. Dibuat/diperbarui via `DeltaSync.initJournal`; file yang hilang dari
  disk otomatis menjadi tombstone (deletion detection).
- **Delta** (format `SMPLDLT1`, berversi): `magic(8) | ver(1) | flag(1) |
  keyCrateLen(4) | keyCrate | dataCrate`. Terenkripsi (keyCrate `SMPLCRT1` +
  XChaCha20-Poly1305) bila password diberikan; polos untuk transfer lokal.
  Payload: arsip biner (manifest JSON + isi catatan plaintext).

**Algoritma merge** (`DeltaSync.importDelta`):

- File identik (hash sama) → skip.
- File hanya ada di delta → tulis.
- File berubah di dua sisi sejak state bersama (hash jurnal lokal ≠ hash
  manifest delta) → **konflik**, diselesaikan sesuai strategi:
  - `keep-both` (default): delta ditulis sebagai
    `n.conflict-<device>-<stamp>.md` — tidak pernah ada data hilang;
  - `newest`: mtime terbaru menang; `ours`: lokal menang; `theirs`: delta menang.
- Tombstone: diterapkan hanya bila hash lokal cocok; lokal berubah → konflik.
- Fail-closed: path traversal/absolut di **manifest maupun entri** ditolak
  sebelum menulis; delta terenkripsi tanpa password → ditolak; tamper → AEAD
  reject. Setelah apply, manifest pengirim disimpan sebagai
  `peer-<deviceId>.json` sehingga delta berikutnya minimal (inkremental).

**CLI** (`apps/simpul`): `sync-init`, `sync-status`, `sync-export
(--peer ID | --peer-journal FILE) [--out] [--encrypt]`, `sync-import <vault>
<delta> [--strategy ...]`.

**Batasan**: tanpa delta-sync jaringan langsung (transport = file); tanpa
merge tiga-arah per-hunk (level granularitas = file).

## 2. TUI Interaktif Paritas Hermes

**Analisis fitur Hermes TUI** yang diadopsi: editing per karakter (bukan
baris-per-baris), riwayat persisten dengan navigasi ↑/↓, autocomplete Tab,
multiline input, pintasan Emacs (Ctrl+A/E/K/U/W), warna ANSI, dan fallback
aman di terminal terbatas.

**Implementasi** (`apps/simpul/lib/tui/`):

- `line_editor.dart` — state machine murni (tanpa I/O, 100% unit-testable):
  - `decodeKeys`: decoder input terminal (ANSI CSI A/B/C/D/H/F, ~1/~3/~4,
    kontrol, UTF-8 multi-byte; byte tak dikenal diabaikan agar paste aman).
  - `LineEditor`: kursor, gerak kata, kill-ring (Ctrl+K/U/W), yank, riwayat
    dengan draft terjaga, autocomplete Tab dengan siklus kandidat
    (kandidat pertama → common prefix terpanjang, Tab berikutnya berputar).
  - `MultilineBuffer`: kelanjutan backslash (`\`) dan blok `/begin … /end`.
- `commands.dart` — `TuiCommands`: `/help /open /search /links /health /ask
  /stats /history /clear /quit`; teks tanpa `/` diperlakukan sebagai `/ask`
  (RAG ekstraktif dengan sitasi). Tab melengkapi perintah + path catatan.
  Riwayat persisten via `TuiHistoryStore` (`.simpul/tui-history.txt`, batas
  500, dapat dioverride `SIMPUL_HISTORY`).
- `repl.dart` — loop interaktif: raw mode (`lineMode=false, echoMode=false`)
  dengan re-render ANSI in-place; hormati `NO_COLOR`/`TERM=dumb`; fallback
  otomatis ke mode baris biasa bila raw mode tidak tersedia (pipe, terminal
  terbatas) — sehingga tetap jalan di Termux/CI.

**CLI**: `simpul tui <vault>` (alias `repl`).

## 3. Tema Terpusat & Settings Lintas Platform (Flutter)

- `ui/theme.dart` — **satu sumber token desain** (`SimpulTheme`): palet gelap
  + terang, skala spacing, radius, `SimpulTheme.theme(brightness, accent)`
  untuk ThemeData, `panelBox`, dan extension `BuildContext` yang
  brightness-aware (`context.simpulPanel`, dll).
- `lib/main.dart` — 45 pemakaian warna hardcoded diganti token tema
  brightness-aware; `MaterialApp` kini memakai `theme`/`darkTheme`/
  `themeMode` dari settings. Halaman Settings lama (hanya koneksi) digantikan
  `SettingsView`.
- `ui/settings_view.dart` — `SettingsView` (dipakai rail desktop, halaman
  "More" mobile, dan build web): **Tampilan** (mode tema Sistem/Gelap/Terang,
  pemilih 5 warna aksen), **Koneksi** (base URL + bearer token, validasi),
  **Perilaku** (host Ollama, path vault, auto-lock menit), seksi Daemon.
- `ui/settings_store.dart` — `AppSettings` persisten via `shared_preferences`
  (dependensi baru, first-party Flutter; diperlukan agar settings bertahan di
  web/desktop/Android).

## Keputusan Desain

- Transport delta = file portabel (konsisten dengan filosofi lokal-first;
  tanpa server, tanpa akun). Konflik default `keep-both` karena tidak ada data
  yang boleh hilang diam-diam.
- TUI ditulis tanpa dependensi eksternal (tidak ada readline FFI) agar tetap
  kompilasi di Termux/web/desktop; raw mode opsional dengan fallback.
- `shared_preferences` dipilih untuk persistensi settings karena bekerja di
  semua target Flutter (web memakai localStorage, desktop file).
