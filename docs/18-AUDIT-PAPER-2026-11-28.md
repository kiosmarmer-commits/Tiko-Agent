# Audit Riset Paper 2026-11-28 — Implementasi & Defer

Sumber: laporan audit "Tiko-Agent Audit Riset Implementasi 2026-11-28" (pemetaan 17 paper
riset agent terhadap basis kode Tiko-Agent). Dokumen ini mencatat apa yang
diimplementasikan dari laporan itu, apa yang di-defer, dan alasannya. Prinsip tetap
additive: tidak ada fitur existing yang diubah kontraknya.

## 1. Diimplementasikan (Fase 27)

### RAG-01 — Rehidrasi chunk RAG pasca-restart (bug P1)

- Sebelumnya `RagPipeline._chunks` in-memory; setelah restart `retrieve()` selalu kosong
  walaupun indeks lexical persisten — runtime tidak pernah memulihkan metadata chunk.
- Kini `ingest()`/`remove()` mem-persist indeks lexical segera (`_saveLexicalQuietly`,
  gagal I/O tidak menggagalkan ingest), dan `TikoRuntime.create()` memanggil
  `restoreChunksFromLexicalIndex()`: chunk direkonstruksi dari id stabil `<docId>#<index>`
  di dokumen FTS yang baru dimuat disk. Non-destruktif, id malformed/legacy dilewati
  tanpa crash.
- Test: `packages/agent_memory/test/rag_rehydration_test.dart` (4 kasus).

### Self-RAG evidence gate (gap)

- Terinspirasi Self-RAG (ICLR 2024) tapi deterministik-heuristik, bukan replikasi paper:
  `SelfRagController.assess()` menilai apakah hasil retrieval layak disuntikkan ke
  system prompt.
- Kebijakan: query kosong/terlalu panjang → tolak; tanpa hit → tolak; mode lexical →
  coverage kata isi (token ≥3 char non-stopword) ≥ ambang (default 0.25); mode embedder →
  skor hybrid terbaik harus finite dan positif (paraphrase tolerance).
- Wiring: `RuntimeContext.selfRagGate` + `onRagGate`; konteks RAG lemah tidak pernah masuk
  prompt; event telemetry bebas-konten `rag.evidence_gate`. Config `rag:` (`evidence_gate`,
  `evidence_gate_min_coverage`, `evidence_gate_max_query_chars`), default on.
- Test: `packages/agent_memory/test/self_rag_controller_test.dart` (10 kasus),
  `packages/tiko_runtime/test/self_rag_context_integration_test.dart` (3 kasus).

### RAG-03 — Telemetry kegagalan embedding (partial → wired)

- `_safeEmbed` kini memanggil `onEmbedError(meta, error)` (hanya meta panjang char, bukan
  isi teks); runtime meng-wire-nya ke event `rag.embed_failed`. Never-raises.

### DOC-01..04 — Perbaikan drift dokumentasi

- DOC-01: `docs/00-INDEX.md` snapshot di-update dari commit/PR lama (`e5db409`/PR #199)
  ke `main` aktual.
- DOC-02: ringkasan roadmap F1–F8 → F1–F10 di `docs/00-INDEX.md`.
- DOC-03: `docs/06` kini menyatakan `SqliteVecIndex` durable default saat SQLite tersedia
  (konsisten docs/04 dan source), bukan lagi `BruteForceVectorIndex` saja.
- DOC-04: status `LayeredMemory` di docs/04 diperjelas "sudah ter-wire ke runtime".

## 1b. Lanjutan implementasi (Fase 28–30)

### RAG-02 — Persistent chunk-vector cache (Fase 28)

- `ChunkVectorCache` (agent_memory): cache vektor chunk yang persisten antar
  restart, sehingga jalur dense tidak selalu re-embed seluruh korpus saat
  startup; kegagalan load bersifat fail-open (lexical tetap jalan).
- Test: `packages/agent_memory/test/rag_rehydration_test.dart`.

### EVAL-01 — Benchmark fixture RAG (Fase 28)

- `RagBenchmark` + fixture JSON bawaan (`test/fixtures/rag_benchmark.json`):
  skema penilaian retrieval deterministik (recall@k) tanpa bergantung korpus
  eksternal; tidak menggantung CI pada sumber luar.
- Test: `packages/agent_memory/test/rag_benchmark_test.dart`.

### LEARN-01 — Feedback loop end-to-end (Fase 29)

- CLI: `tiko feedback <session> --up|--down` (route via `rt.applyTurnFeedback`:
  skill metrics durable + evolution ledger) dan `tiko skills feedback <slug>`.
- Flutter chat: aksi thumbs up/down pada pesan asisten
  (`AgentApiClient.sendSessionFeedback` + `AgentRepository`).
- Sink observability: kegagalan sink SkillRegistry kini log ke stderr, bukan
  hilang senyap; durabilitas feedback diuji lintas restart runtime
  (`learn01_feedback_flow_test.dart`).

### ToT/LATS bounded deep-solve — tool `deep_solve` (Fase 30)

- Laporan menandai Tree of Thoughts / LATS sebagai gap berbiaya tinggi;
  implementasinya "adopt selectively" (bukan replikasi paper: tanpa MCTS +
  value-head), planner bounded di `packages/tiko_runtime/lib/src/deep_solve.dart`:
  1. *Expand*: satu panggilan LLM meminta `branching` pendekatan berbeda.
  2. *Value*: tiap kandidat dinilai LLM judge `SCORE:`/`REASON:` (pola
     SelfRewardJudge — LATS-style value function).
  3. *Refine*: kandidat terbaik dipecah per level sampai `depth`.
- Budget gating keras: `max_llm_calls` (1–64), `max_wall_clock_sec` (≥5),
  `max_tokens_per_call`; semua kegagalan LLM degenerate ke kandidat terbaik
  yang tersedia (never-raises terhadap caller).
- Tidak masuk jalur chat default: dieksekusi lewat tool `deep_solve` yang
  dipanggil model saat task menuntut eksplorasi; konfigurasi `deep_solve:`
  (`enabled` default **off**, `branching` 1–4, `depth` 1–3). Wiring runtime
  membuat engine + tool hanya bila enabled dan ada provider auxiliar; event
  telemetry `deep_solve.done` bebas-konten.
- Test: `packages/tiko_runtime/test/fase30_deep_solve_test.dart` (7 kasus:
  alur penuh, LLM mati, cap, parseVerdict strict, validasi tool, parser
  config fail-open, wiring on/off).

### Task classifier + algorithm router — advisory `task.mode` (Fase 31)

- Laporan §7.2 mengusulkan `TaskMode` internal tanpa menambah 20 agent baru;
  implementasinya `TaskClassifier` heuristik deterministik di
  `packages/tiko_runtime/lib/src/task_classifier.dart` — TANPA panggilan LLM,
  tanpa hak mengubah security/permission, dan *advisory-only*: jalur eksekusi
  AgentLoop ReAct tidak berubah.
- Mode mengikuti tabel §7.2: `fast` / `tool` / `plan` / `deepReasoning` /
  `research` / `coding` / `knowledge`; prioritas deterministik coding >
  research > knowledge > plan > deep > tool > fast; input panjang tanpa
  sinyal → `tool` (bukan fast); perintah internal `/…` tidak diklasifikasi.
- Telemetry bebas-konten: event `task.mode` (mode + nama sinyal + panjang
  input, tanpa isi pesan) dan field baru `ChatRunResult.taskMode` (kosong
  bila off/internal) — JSON result kini menyertakan `task_mode`.
- Konfigurasi `task_classifier:` (`enabled` default **on**,
  `fast_max_chars` 200, keyword tambahan per mode `*_keywords`) — parser
  fail-open.
- Test: `packages/tiko_runtime/test/fase31_task_classifier_test.dart`
  (16 kasus: 12 unit classifier, parser fail-open, wiring event + result,
  disabled, skip perintah internal).

### Inter-agent messaging umum — group chat AutoGen-style (Fase 35)

### MemGPT-style control-flow paging (Fase 36)

- Laporan §6 #9 menandai MemGPT "partial" (layered/curated memory +
  compaction ada, control-flow paging belum); implementasinya
  `ContextPager` di `packages/agent_memory/lib/src/context_pager.dart` —
  BUKAN replikasi penuh (tanpa fungsi self-edit `core_memory_append`):
  1. *Page-out deterministik*: pesan di luar working window
     (`SessionStore.recent` minus `keepRecent`) dipaging keluar ke layer
     episodic per halaman bounded (`max_chars_per_entry`), idempoten via
     fingerprint FNV-1a (state persist di `data/context_paging_state.json`,
     cap `max_state_entries`); data asli TETAP UTUH di session store.
  2. *Page-in on-demand*: tool `memory_page` action `page_in` — kontrol di
     tangan model (intinya control-flow MemGPT), filter tag `paged` +
     binding sesi + wajib overlap lexical (skor 0 ditolak).
  3. *Status*: hitungan halaman per sesi untuk observability.
- Never-raises: kegagalan store → `PageOutReport.error`, bukan exception.
- Tool `memory_page` (page_out|page_in|status, risk low) terdaftar selalu
  di tool registry (pola `layered_memory`), tanpa config baru.
- Test: `packages/agent_memory/test/context_pager_test.dart` (PAGE-1..5:
  page-out + idempoten, page-in scoped + anti-bocor, sejarah pendek,
  store gagal never-raises, tool end-to-end).

### LATM maker/user tool-generation pipeline (Fase 37)

- Laporan §6 #16 menandai LATM "partial" (`ToolForge` ada, pipeline
  maker/user terpisah belum); implementasinya `ToolMakerPipeline` di
  `packages/tiko_runtime/lib/src/tool_maker_pipeline.dart` — pemisahan
  peran LATM (bukan replikasi penuh: tanpa caching lintas-instance dan
  server functions terdistribusi):
  1. **Maker**: LLM auxiliar terpisah mendesain `ForgedToolDef` (nama
     ber-namespace `made_`, command sandbox, 2–16 contract tests); turn
     maker tanpa tool dan tanpa akses workspace.
  2. **Validator**: contract tests dijalankan [ToolForge] yang sudah ada
     (reuse jalur NEW-12; fail-closed tanpa sandbox — tidak ada instalasi).
  3. **User**: agent utama memakai tool via registry biasa; permission
     gate tetap berlaku (risk `high`).
- Pipeline never-raises; kegagalan parse/validasi/tests → report
  `ok: false` dengan tahap penanda (`maker`/`validate`/`contract_tests`);
  nama bentrok ditolak sebelum tests; namespace `made_` mencegah tabrakan
  dengan tool bawaan.
- Konfigurasi `tool_maker:` (`enabled` default **off**, `max_tests` 1–16,
  `max_command_parts` 2–32) — parser fail-open. Tool `tool_maker` hanya
  terdaftar bila enabled DAN ada LLM auxiliar; event `tool_maker.installed`
  /`tool_maker.rejected` bebas-konten.
- Test: `packages/tiko_runtime/test/fase37_tool_maker_test.dart` (7 kasus:
  alur penuh, parser def + batas keras, contract tests gagal fail-closed,
  nama bentrok, maker gagal never-raises, parser config, wiring on/off).

## 1c. Adopsi perbandingan Grok Bot (Fase 38–41, 2026-11-28)

Empat fitur hasil analisa perbandingan fitur bot Tiko-Agent vs Grok Bot
(xAI; beta 11 Agustus 2026, GA 1.0 11 November 2026) — diadopsi *additive*
menyesuaikan konvensi repo (deterministik-first, fail-closed, default off,
never-raises), bukan replikasi produk.

### Routines — rekam & replay langkah tool-call (Fase 38)

- Paritas Grok Bot "observe → retain → rerun": resep routine direkam dari
  langkah tool-call yang SUKSA (fail-fast terhadap error) dan dijalankan
  ulang deterministik tanpa LLM.
- `RoutineRecorder` (per sesi, cap `max_steps`, truncation
  `max_args_chars`), `RoutineStore` (`<dataDir>/routines/<id>.json`,
  atomic tmp+rename, fail-open terhadap file korup), `RoutineRunner`
  (replay berurutan via executor terinjeksi; opsi `dry_run`,
  `continue_on_error`; statistik run disimpan; never-raises).
- Tool `routine` (record_start/record_stop/list/show/run/delete, risk
  `high`) + config `routine:` (`enabled` default **off**, `max_steps` 1–256,
  `max_args_chars` ≥64) — parser fail-open. Perekaman hidup via hook audit
  di `chatWithStatus`; hanya aktif saat operator memulai rekaman.
- Test: `packages/tiko_runtime/test/fase38_routine_test.dart`
  (ROUTINE-1..7).

### AuthorizationMemory — smart approvals dengan TTL (Fase 39)

- Paritas Grok Bot "smarter approvals": aksi (tool + hash argumen + scope)
  yang sudah di-approve disimpan ber-TTL; aksi identik berikutnya melewati
  approval tanpa mengurangi fail-closed.
- `AuthorizationMemory` (persist `<dataDir>/authorization_memory.json`,
  cap `max_entries`, scope `session:<id>` atau `*`), fingerprint
  `stableArgsHash` semantik sama dengan hash ledger approval (key internal
  `_`* dibuang, normalisasi key-sorted JSON + FNV-1a 32-bit).
- Fail-closed permanen: `never_cache_tools` (default `tool_maker`,
  `spawn_subagent`, `routine`) tidak pernah diotorisasi otomatis; entry
  kedaluwarsa dihapus; kegagalan disk tidak menghasilkan otorisasi palsu;
  capa­bility token tetap diterbitkan per aksi.
- Tool `authz` (list/revoke/clear, risk `medium`) — memberi otorisasi baru
  HANYA lewat approval sungguhan; config `authorization_memory:`
  (`enabled` default **off**, `ttl_minutes` 5–10080, `max_entries` 1–2000,
  `never_cache_tools`) — parser fail-open.
- Test: `packages/tiko_runtime/test/fase39_authz_test.dart` (AUTHZ-1..7).

### Review learnings queue (Fase 40)

- Paritas Grok Bot "Review learnings": pelajaran hasil interaksi bot
  diantrikan dan WAJIB di-approve owner sebelum masuk memori bot.
- `LearningProposal` + `ReviewLearningsStore` (persist
  `<dataDir>/review_learnings.json`, cap `max_proposals`, konten di-cap,
  keputusan idempoten aman: hanya pending yang bisa diputus).
- Approve menulis ke `BotProfile.learnings` (field baru, cap
  `max_learnings_per_bot` 1–256) via callback fail-closed — tool tidak
  pernah menulis memori langsung; pelajaran disuntik setelah persona bot
  (`_botPersonaFor`). Bot tanpa id valid → penulisan gagal dilaporkan.
- Tool `review_learnings` (propose/list/approve/reject, risk `medium`) +
  config `review_learnings:` (`enabled` default **off**) — parser fail-open.
- Test: `packages/tiko_runtime/test/fase40_review_learnings_test.dart`
  (LESSON-1..6).

### Team Bot sharing & per-person permission (Fase 41)

- Paritas Grok Bot 1.0 "Team Bots": bot ber-owner (`owner` userKey) hanya
  bisa diaktifkan owner atau userKey yang di-share (`sharedWith`) —
  penolakan fail-closed di level turn dan `/bot use`; event
  `bot.access_denied` bebas-konten.
- Backward-compatible: bot lama tanpa `owner` tetap publik; `/bot share
  <id> <userkey>` / `/bot unshare` hanya boleh dilakukan owner; `/bot
  show` menampilkan owner/shared/pelajaran.
- REST daemon (`/v1/bots`) menerima field tambahan `owner` (create) dan
  `owner`/`shared_with` (update) — additive.
- Test: `packages/tiko_runtime/test/fase41_team_share_test.dart`
  (TEAMSHARE-1..5).

## 3. Batasan sadar

- `embedderConfigured` hanya berarti embedder terkonfigurasi, bukan bukti embedding
  sukses per-request; metadata "vector path actually used" menyusul bersama RAG-02.
- Gate lexical menilai overlap token, bukan semantik; false negative mungkin untuk
  paraphrase ekstrem tanpa embedder (karena itu jalur embedder diprioritaskan).
