# Bot Mode — Persona Persisten per Chat — 15 November 2026

Bot Mode (rekomendasi #4 dari sesi Hermes-parity): persona bot persisten per chat dengan model sendiri, mengikuti pola character card (SillyTavern: name/description/personality/scenario) dan persistent assistant objects (OpenAI Assistants API: instructions + model + tools per assistant).

## Desain

### `BotProfile` + `BotStore` (`packages/tiko_runtime/lib/src/bot_mode.dart`)

- **BotProfile**: `id` (slug `[a-z0-9][a-z0-9_-]{0,63}`), `name`, `persona` (prompt wajib diikuti), `model` (provider id opsional; null = provider default router), `greeting`, `createdAt`/`updatedAt`.
- **BotStore**: satu file JSON per bot di `dataDir/bots/<id>.json`; binding sesi→bot di `dataDir/bots/bindings.json`. Penulisan atomik (tmp+rename). File JSON korup dilewati, tidak menggagalkan store. `delete` menghapus binding sesi yang terikat otomatis.
- Persisten antar restart: profil dan binding dimuat ulang saat runtime dibuat.

### Slash command `/bot` (intercepted di funnel `chatWithStatus`)

| Perintah | Efek |
|---|---|
| `/bot` atau `/bot list` | daftar bot + binding sesi ini (`[aktif]`) |
| `/bot new <id> <nama>` | buat profil baru (id tervalidasi slug) |
| `/bot persona <id> <teks>` | tetapkan prompt persona |
| `/bot model <id> <provider\|default>` | ikat provider chat untuk bot ini |
| `/bot allow <id> <tool1,tool2,...>\|clear` | tetapkan allowlist tool bot (nama divalidasi terhadap registry) |
| `/bot import <path>` | impor character card SillyTavern V1/V2/V3 (JSON atau PNG ber-chunk `chara`/`ccv3`) menjadi bot baru (event `bot.imported`) |
| `/bot use <id>` | aktifkan bot untuk sesi ini (event `bot.activated`) |
| `/bot off` | nonaktifkan bot sesi ini (event `bot.deactivated`) |
| `/bot show <id>` | detail profil |
| `/bot delete <id>` | hapus bot + semua binding (event `bot.deleted`) |

Event tambahan: `bot.created`, `bot.updated`.

### Injeksi ke turn

- **Persona**: bila sesi terikat bot, `RuntimeContext.botPersona` disuntikkan ke system prompt setelah persona SOUL.md: `Bot persona (wajib diikuti untuk sesi ini): ...`.
- **Model**: routing memakai `preferredProviderId: _sessionModel[sessionId] ?? bot.model` — override `/model` per sesi masih menang atas model bot.
- Bekerja di semua platform (CLI/TUI/API/Flutter/gateway) karena intercept terjadi di `chatWithStatus`.

## Keputusan desain

1. **Binding per sesi, bukan per user** — satu bot bisa aktif di banyak sesi sekaligus; sesi berbeda bisa memakai bot berbeda.
2. **Model bot = fallback, bukan paksaan** — `/model` eksplisit pada sesi tetap menang; `/model default` kembali ke model bot.
3. **Persona bot terpisah dari SOUL.md** — SOUL.md tetap persona workspace yang immutable; bot persona adalah lapisan per-chat yang bisa dibuat/dihapus saat runtime.
4. **Tanpa config baru** — Bot Mode selalu tersedia; tidak ada flag fitur yang perlu diaktifkan.

## Tool allowlist per bot (fail-closed, 2026-11-16)

Setiap bot punya `tool_allowlist` (tersimpan di `data/bots/<id>.json`). Sesi yang
ter-bind ke bot hanya dapat melihat dan mengeksekusi tool pada daftar itu:

- **Kosong = ditolak.** Bot tanpa allowlist tidak mewarisi tool host — turn di
  sesi ter-bind ditolak dengan pesan panduan (sama dengan semantik `BotRouter`
  di agent_core: empty allowlist bukan berarti "semua tool").
- **Dua lapis penegakan:** `toolFilter` menyembunyikan tool di luar allowlist
  dari prompt, dan `_BotToolGate` menolak eksekusi tool di luar allowlist pada
  level gate (prompt-level saja tidak cukup karena gate tetap mengenal
  permukaan penuh).
- `/bot allow <id> <tool1,tool2>` memvalidasi nama terhadap registry dan
  menolak nama tak dikenal; `/bot allow <id> clear` mengosongkan (kembali
  fail-closed). Sub-perintah `/bot` (termasuk `/bot off`) tidak terdampak
  penegakan sehingga bot selalu bisa dinonaktifkan.

1. `/bot list` kosong → panduan pembuatan.
2. `/bot new` + `/bot persona` + `/bot show` → profil tersimpan dan tampil.
3. `/bot use` → `[aktif]` di list; `/bot off` → lepas (dan pesan saat belum terikat).
4. e2e: bot aktif → persona terlihat di body request ke provider, routing mengikuti model bot, `/bot off` kembali ke provider default.
5. id tidak dikenal ditolak.
6. Restart runtime → profil dan binding tetap ada.

## Routing gateway (unifikasi 2026-11-16)

Sebelumnya ada dua sistem bot paralel yang tidak terhubung: `BotStore` (slash `/bot`, persona per sesi) dan `BotRegistry`/`BotModeGate` di agent_core (binding `AgentSpec` untuk grup, persistensi `data/bots.json`). Kini **satu sumber kebenaran**: routing grup di `agentd` memakai `BotGroupRouter` (`packages/tiko_runtime/lib/src/bot_group_router.dart`) yang membaca `BotStore` yang sama dengan `/bot`.

Perilaku pesan masuk di `agentd`:

| Kondisi | Aksi |
|---|---|
| Chat privat | bypass — perilaku single-agent tetap |
| Grup, mention handle = id bot (`@helper`) | **dispatch**: sesi diikat ke bot (semantik `/bot use`) → persona + model bot disuntik otomatis oleh funnel chat |
| Grup, tanpa mention bot | drop — agent utama tidak menjawab obrolan grup yang tidak ditujukan ke bot |
| Grup, tanpa profil bot terdaftar | bypass — Bot Mode off |

Mention diparse dengan `MentionParser` (agent_core): email, code span/fence, dan pseudo-mention `@everyone/@here/@all` diabaikan. Mention bot terakhir yang menang bila beberapa bot di-mention; me-mention bot lain me-rebind sesi; `/bot off` lepas.

Status: `wired` untuk persona+model (dispatch menjawab lewat persona bot); `unit-tested` untuk router-nya. Belum `verified-e2e` terhadap Telegram live.

## Impor character card SillyTavern (B5, 2026-11-16)

`/bot import <path>` membaca character card dari file di dalam workspace
(JSON atau PNG) dan membuat bot baru:

- **Format:** V1 (field di root), V2 (`spec: 'chara_card_v2'` + blok `data`),
  V3 (`chara_card_v3`, backward-compatible). PNG memakai chunk `tEXt`
  keyword `ccv3` (diprioritaskan) atau `chara`, isi base64 UTF-8 JSON.
- **Komposisi persona:** `description` + `personality` + `scenario` +
  `system_prompt` digabung; `first_mes` menjadi greeting bot.
- **Keamanan:** path dijail ke workspace via `PathSafety.resolveInRoot`,
  ukuran input dibatasi (JSON 2 MB, PNG 32 MB), teks di-cap, id di-slugify
  dari nama karakter dengan sufiks `-2`, `-3`, ... bila collision.
- **Fail-closed:** bot hasil impor lahir dengan allowlist tool kosong — turn
  ditolak sampai operator mengatur `/bot allow <id> <tool1,tool2>`.

## Batasan

- Impor character card hanya membaca field teks inti; `character_book`,
  `alternate_greetings`, dan aset V3 belum dipetakan.
- Handle mention dibatasi 32 karakter oleh `MentionParser`; profil bot dengan id lebih panjang tidak bisa di-mention dari gateway.
- Routing gateway tidak membawa konsep `AgentSpec` (kelas `BotRegistry`/`BotRouter` di agent_core tetap tersedia untuk routing berbasis tim multi-agent, terpisah dari persona bot).
