# Bot Mode — Persona Persisten per Chat — 15 November 2026

Bot Mode (rekomendasi #4 dari sesi Hermes-parity): persona bot persisten per chat dengan model sendiri, mengikuti pola character card (SillyTavern: name/description/personality/scenario) dan persistent assistant objects (OpenAI Assistants API: instructions + model + tools per assistant).

## Desain

### `BotProfile` + `BotStore` (`packages/tiko_runtime/lib/src/bot_mode.dart`)

- **BotProfile**: `id` (slug `[a-z0-9][a-z0-9_-]{0,63}`), `name`, `persona` (prompt wajib diikuti), `model` (provider id opsional; null = provider default router), `greeting`, `createdAt`/`updatedAt`.
- **BotStore**: satu file JSON per bot di `dataDir/bots/<id>.json`; binding sesi→bot di `dataDir/bots/bindings.json`. Penulisan atomik (tmp+rename). File JSON korup dilewati, tidak menggagalkan store. `delete` menghapus binding sesi yang terikat otomatis.
- Persisten antar restart: profil dan binding dimuat ulang saat runtime dibuat.

### Slash command `/bot` (intercepted di funnel `chatWithStatus`)

| Perintah | Efek |
|---|---|
| `/bot` atau `/bot list` | daftar bot + binding sesi ini (`[aktif]`) |
| `/bot new <id> <nama>` | buat profil baru (id tervalidasi slug) |
| `/bot persona <id> <teks>` | tetapkan prompt persona |
| `/bot model <id> <provider\|default>` | ikat provider chat untuk bot ini |
| `/bot use <id>` | aktifkan bot untuk sesi ini (event `bot.activated`) |
| `/bot off` | nonaktifkan bot sesi ini (event `bot.deactivated`) |
| `/bot show <id>` | detail profil |
| `/bot delete <id>` | hapus bot + semua binding (event `bot.deleted`) |

Event tambahan: `bot.created`, `bot.updated`.

### Injeksi ke turn

- **Persona**: bila sesi terikat bot, `RuntimeContext.botPersona` disuntikkan ke system prompt setelah persona SOUL.md: `Bot persona (wajib diikuti untuk sesi ini): ...`.
- **Model**: routing memakai `preferredProviderId: _sessionModel[sessionId] ?? bot.model` — override `/model` per sesi masih menang atas model bot.
- Bekerja di semua platform (CLI/TUI/API/Flutter/gateway) karena intercept terjadi di `chatWithStatus`.

## Keputusan desain

1. **Binding per sesi, bukan per user** — satu bot bisa aktif di banyak sesi sekaligus; sesi berbeda bisa memakai bot berbeda.
2. **Model bot = fallback, bukan paksaan** — `/model` eksplisit pada sesi tetap menang; `/model default` kembali ke model bot.
3. **Persona bot terpisah dari SOUL.md** — SOUL.md tetap persona workspace yang immutable; bot persona adalah lapisan per-chat yang bisa dibuat/dihapus saat runtime.
4. **Tanpa config baru** — Bot Mode selalu tersedia; tidak ada flag fitur yang perlu diaktifkan.
