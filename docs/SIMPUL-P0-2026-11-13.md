# Simpul P0 — Fondasi Vault Index Kompatibel Obsidian (2026-11-13)

Implementasi fondasi P0 proyek **Simpul** (PRD Google Drive `rnd/obsidian clone`,
file 00–10) di dalam repo Tiko-Agent: aplikasi catatan lokal-first dengan
Markdown sebagai sumber kebenaran dan SQLite indeks yang selalu bisa dibangun
ulang (rebuild-able).

## Kompatibilitas Obsidian (referensi terverifikasi)

Sumber: `help.obsidian.md` — halaman *Internal links*, *Embedding files*,
*Properties*, *Tags*.

- Wikilink: `[[Note]]`, `[[Note.md]]`, `[[folder/Note]]`, `[[Note|Display]]`,
  `[[Note#Heading]]`, `[[Note#^block-id]]`, `[[#Heading]]` (note sama).
- Embed: `![[Note]]`, `![[img.png|300]]`, `![[Doc.pdf#page=3]]` — embed tidak
  dihitung sebagai edge graf (sesuai Graph view Obsidian).
- Markdown link: `[text](path.md)` dengan percent-decoding (`%20` → spasi);
  `http(s):`, `mailto:`, `file:`, dan anchor `#...` diabaikan.
- Tag: `#a/b` bertingkat, tanpa spasi, minimal satu non-digit, trailing
  punctuation dibuang; tag di heading tidak dihitung.
- Resolusi target: exact path (tanpa `.md`) lebih dulu, lalu basename di
  seluruh vault (path terpendek menang — perilaku Obsidian).
- Karakter invalid di target tidak diikuti: `# | ^ : %% [[ ]]` (pemisah
  anchor/alias sudah ditangani parser).
- Frontmatter properties: `title`, `tags`, `aliases`, nilai bertipe
  (bool/num/list inline `- item` maupun `[a, b]`).

## Skema SQLite (PRD `09-arsitektur-data.md` §3)

`meta`, `notes`, `links` (`dst_id` nullable untuk broken link), `tags`,
`props`, `chunks`, `chunks_fts` (FTS5).

Deviasi terdokumentasi: `chunks_fts` memakai FTS5 biasa (konten tersimpan di
tabel virtual), bukan contentless, agar `snippet()` (FR-35) tetap tersedia —
contentless FTS5 tidak mendukung snippet tanpa kolom konten eksternal.

## Keputusan desain

1. **Fallback JSON** — `SqliteVaultIndex.tryOpen` mengembalikan `null` bila
   `libsqlite3` tidak ada (pola sama dengan `SqliteMemoryStore.tryOpen` di
   agent_memory). `JsonVaultIndex` punya semantik identik: tulis atomik
   tmp+rename, lazy-load dari disk, scoring linear scan (judul 3.0, kemunculan
   chunk 1.0, frasa 2.0). Path JSON-lah yang teruji penuh di sandbox/CI karena
   tidak ada libsqlite3.
2. **JsonVaultIndex lazy-load** — bug ditemukan saat smoke CLI: instance baru
   tidak membaca file indeks yang sudah ada sehingga `search`/`health`
   mengembalikan kosong. Diperbaiki dengan `_ensureLoaded()` pada
   `search`/`backlinks`/`health` + test round-trip lintas instance.
3. **CSR node id** = indeks padat 0..N-1 atas daftar path terurut; embed,
   self-link, dan target duplikat dilewati.
4. **Generator** menolak direktori existing (`ArgumentError`) agar vault
   benchmark selalu reproducible; `.obsidian/app.json` ikut dibuat agar vault
   bisa dibuka langsung di Obsidian.
5. **CLI fail-closed** — exit 2 untuk argumen tidak valid, exit 1 untuk
   kegagalan runtime; output JSON satu baris per perintah.

## Hasil benchmark awal (sandbox, backend JSON, 200 catatan)

- Scan: 206 ms (~971 catatan/detik), index: 15 ms (~13.333 catatan/detik).
- Search p50 933 µs, p95 1526 µs, rata-rata 14,8 hit.
- CSR build 1 ms; 200 node, 183 edge, 16 orphan.

Angka ini baseline JSON fallback; SQLite (FTS5+bm25) diharapkan lebih baik
untuk vault besar dan akan diukur di lingkungan dengan libsqlite3 (BM-07).

## Smoke CLI end-to-end

```
simpul generate --notes 200 --seed 42 --out <dir>   → 200 notes, 199 links, 7 broken, 9 embeds
simpul index <vault>                                → backend json, scan 263 ms, index 27 ms
simpul search <vault> "tag:kriptografi" --limit 2   → hit sesuai tag
simpul health <vault>                               → 200 catatan, 7 broken, 0 orphan
simpul links <vault> <note>                         → backlink
simpul bench <vault> --iterations 20                → laporan BM-02..06
```
