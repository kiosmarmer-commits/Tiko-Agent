## Deteksi komunitas Louvain (GRA-L05)

- Graf CSR diperlakukan **undirected**: setiap tautan berbobot 1.0 di kedua
  arah; tautan dua arah menumpuk menjadi bobot 2.0; self-loop dan tautan ke
  diri sendiri diabaikan pada level dasar.
- Algoritma Louvain standar multi-level: greedy perpindahan node
  (`gain = k_in/m − Σtot·k_i/(2m²)`, epsilon 1e-12) hingga tidak ada perbaikan,
  lalu agregasi komunitas menjadi super-node dengan self-loop intra-komunitas
  berkonvensi `2w`, ulang hingga tidak ada pengurangan ukuran graf
  (maks 8 level, 12 pass per level).
- Modularitas final dihitung ulang di **graf original** (bukan graf agregat)
  dengan formula ordered-pair `Q = (1/2m) Σ_ij [A_ij − k_i·k_j/(2m)]·δ(c_i,c_j)`,
  termasuk kontribusi self-loop diagonal hasil agregasi.
- **Deterministik penuh**: urutan node CSR tetap, tie memilih kandidat pertama,
  tanpa RNG — dua pemanggilan pada graf sama menghasilkan partisi identik
  (diverifikasi test).
- Cycle C12 secara teori modularitas optimal terpecah menjadi dua busur
  (Q ≈ 0.028 > Q(1 komunitas) = 0), sehingga test ring mengasersi
  `modularity ≥ 0` tanpa crash; test complete graph K6 mengunci ekspektasi
  "tetap satu komunitas" (memecah klik menurunkan Q).

## Perbaikan bug nyata di luar batch

- **`resolveTarget` kini menerima target ber-ekstensi** (`[[Note.md]]`, gaya
  yang juga valid di Obsidian): fallback strip `.md` sebelum lookup
  `byPath`/`byBasename`. Sebelumnya seluruh tautan `[[Note.md]]` tidak pernah
  menghasilkan edge di `GraphCsr.build`, indeks tautan, maupun health report.
- Perbaikan Louvain saat iterasi test:
  1. Pemetaan antar-level salah — label komunitas level lama dipakai sebagai
     indeks graf agregat (RangeError dan partisi bisa hilang). Kini
     `_aggregate` mengembalikan mapping label→indeks dan `communityOf` selalu
     dikomposisi sebelum break, termasuk saat semua node bergabung jadi satu
     komunitas.
  2. Modularitas mengabaikan self-loop diagonal hasil agregasi
     (`A_ii − k_i²/2m` kini dihitung dari bobot self-loop tersimpan).

## Sinkronisasi inkremental end-to-end (NFR-S05, NFR-08)

- `VaultIndex.stats()` baru di kedua backend: `path → (mtimeNs, sizeBytes,
  hash)` dari tabel `notes` / cache JSON (dengan lazy-load `_ensureLoaded()`).
- `VaultSync.apply(index, vaultDir)`: ambil `stats()` → `VaultScanner.diff`
  (mtime+size, hash sebagai konfirmasi) → `upsert` file berubah →
  `removePaths` file hilang. Hasil `SyncResult{added, updated, removed,
  unchanged}` plus `toJson()` untuk output CLI.
- CLI `simpul sync <vault>`: membuka index existing (bukan menimpa), sehingga
  hanya file berubah yang diproses. Smoke test vault 150 catatan: tambah 1 +
  revisi 1 + hapus 1 → `added:1, updated:1, removed:1, unchanged:148`;
  pemanggilan kedua tanpa perubahan → semua `unchanged` (idempoten).

## Saran tautan otomatis (AI-25)

- `LinkSuggester.suggest(notes)`: satu vektor per catatan dari teks
  representatif (judul + seluruh chunk), pairwise cosine int8, pasangan yang
  sudah tertaut (dua arah, di-resolve via `resolveTarget`) dikecualikan.
- Default `minScore` 0.35, `limit` 20, dan **fail-closed** `maxNotes` 5000
  (vault lebih besar menolak dengan `ArgumentError`, bukan OOM).
- Saran bersifat advisory — pemanggil (UI/CLI) yang memutuskan. Noise floor
  feature hashing (char-trigram) diukur ≈ 0.1; pasaran satu-topik di vault
  sintetis mencapai 0.68–1.0, pemisahan aman pada `minScore ≥ 0.2`.
